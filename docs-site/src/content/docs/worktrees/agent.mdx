`kunj agent` runs a coding agent inside a [tmux](https://github.com/tmux/tmux) session for a
worktree. The session keeps running when you close the terminal, and running the command again
reattaches to it. It is the host-side counterpart of `kunj ct agent`, which does the same inside a
[branch container](../../containers/overview/).

```bash
kunj agent                 # the current branch's worktree
kunj agent fix/login       # another worktree
kunj agent status fix/login
kunj agent stop fix/login
```

`start` is the default action, so `kunj agent fix/login` starts (or reattaches). `status` says
whether the session exists and `stop` kills it. All three take `--json`.

The command is `agent.command` (default `claude`); `--command <cmd>` overrides it for one run. The
agent starts in the worktree's directory with `KUNJ_BRANCH`, `KUNJ_REPO` and `KUNJ_WORKTREE` set.
`kunj agent` needs a terminal, and works from inside a tmux pane too.

## Antigravity

`--agent antigravity` runs the [Antigravity CLI](https://antigravity.google/) (`agy`) instead of
`agent.command`; `agent.antigravityCommand` (default `agy`) sets its command and flags.
`--agent claude` runs Claude Code (`agent.command` when that runs claude, else `claude`).
`--command` wins over both.

```bash
kunj agent fix/login --agent antigravity --session gemini
```

Only Claude Code tells kunj when it waits for input, so an Antigravity agent shows as running while
its session lives, never as waiting. `kunj ct agent` runs only `container.agentCommand`.

## Secrets

The agent gets the branch's host [secrets](../../configuration/secrets/) (`kunj secret`, whose targets include `host`) as
environment variables, and their file deliveries (such as `.env`) are written into the worktree
first. In tmux the agent runs under `kunj run --branch <branch>`, which opens the secret store inside
the session, so no value is ever in a command line; without tmux kunj does the same before starting
the agent. `kunj worktree shell` gives its shells the same environment. Any other command can get it
too:

```bash
kunj run -- npm run dev
kunj run --branch fix/login -- $SHELL -l
```

`kunj run` passes on the command's exit code. A file that git does not ignore is not written, with a
warning, and the command still runs. When the secret store cannot be opened (the Keychain item is
missing, or a wrong passphrase three times), the command does not start; in an agent or shell tmux
session the error stays on screen until you press Enter.

## Several agents in one worktree

`--session <id>` runs another agent next to the default one, in its own tmux session; the id is 1
to 32 letters, digits, `_` or `-`. `start`, `status` and `stop` with `--session` act on that agent,
and `stop --all` ends the default agent and every `--session` one.

```bash
kunj agent fix/login --session review       # start or reattach a second agent
kunj agent stop fix/login --session review
kunj agent stop fix/login --all
```

`stop` with `--session` or `--all` exits 0 even when nothing was running; with `--json` it lists
what it ended in `stopped`. Without `--session`, `status` reports the worktree as running when any of
its agents runs, and lists them in `sessions`.

## Without tmux

tmux is optional. When it is not installed, `start` runs the command directly in your terminal,
through your login shell, after one line on stderr:

```
tmux is not installed: the agent stops when this terminal closes (brew install tmux to keep it running)
```

The agent's exit code becomes `kunj agent`'s. `--no-tmux` does the same when tmux is installed.
Without tmux `status` reports `running: null` (unknown) and `stop` fails with `tmux-missing`, since
there is no session to stop.

## Session names

One tmux server serves the whole machine, so kunj picks the session name rather than using the
branch name. It is the branch container's name (`kunj-<repo>-<branch>-<hash>`, the hash covering the
exact branch name so `feature/x` and `feature-x` differ) with every `.` and `:` replaced by `-`,
because tmux treats those as target separators. An agent started with `--session <id>` adds
`-a-<id>` to it.

## In the worktree list

`kunj worktree list --json` adds an `agent` field to every worktree that exists and is on a branch:

```json
{
  "agent": {
    "running": true,
    "session": "kunj-shop-api-fix-login-timeout-3fa9c1",
    "state": "waiting",
    "sessions": [
      { "session": "kunj-shop-api-fix-login-timeout-3fa9c1", "id": null, "state": "running" },
      { "session": "kunj-shop-api-fix-login-timeout-3fa9c1-a-review", "id": "review", "state": "waiting" }
    ]
  }
}
```

`session` is the default agent's session. `running` is true when any of the worktree's agents runs,
and `state` is `waiting` when any of them waits for you. `sessions` lists the running ones (`id` is
null for the default agent). `running` is `null`, and `sessions` absent, when tmux is not installed. The listing asks tmux once, not once per worktree,
and skips it with `--no-status`.
