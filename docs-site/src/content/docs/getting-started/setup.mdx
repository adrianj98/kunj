`kunj setup` is a short interactive wizard you run once after installing. It does three things,
in this order:

1. Adds a set of short shell aliases for kunj commands to your shell's startup file.
2. Optionally connects kunj to Jira Cloud.
3. Optionally installs the VS Code extension and the macOS menu bar app.

It does not configure AI. For that, see [AWS Bedrock](../../integrations/aws-bedrock/).

```bash
kunj setup
```

## 1. Shell aliases

kunj works out your shell from `$SHELL` (zsh, bash or fish). If it can't tell, it asks; pass
`--shell zsh` to choose yourself. It then shows the file it will edit:

| Shell | File |
| --- | --- |
| zsh | `~/.zshrc` |
| bash | `~/.bashrc`, or `~/.bash_profile` when there is no `~/.bashrc` |
| fish | `~/.config/fish/config.fish` |

and the aliases it will add:

| Alias | Runs |
| --- | --- |
| `kj` | `kunj` |
| `ksw` | `kunj switch` |
| `kcom` | `kunj commit` |
| `kpr` | `kunj pr` |
| `klist` | `kunj list` |
| `kclean` | `kunj clean` |

<Aside type="caution">
There is no `kunj clean` command at the moment, so the `kclean` alias only prints an error. You can
delete that line from the file.
</Aside>

It asks **Continue with installation?** (default yes). If the file doesn't exist it is created. The
aliases are appended as one block between two marker comments:

```bash
# Kunj CLI Aliases
# Generated by kunj setup
# https://github.com/adrianj98/kunj

alias kj="kunj"
alias ksw="kunj switch"
alias kcom="kunj commit"
alias kpr="kunj pr"
alias klist="kunj list"
alias kclean="kunj clean"
# End Kunj CLI Aliases
```

If the block is already there, kunj asks **Kunj aliases already exist. Overwrite them?**
(default no) and replaces the block only if you say yes. Run `kunj setup` again any time to
rewrite it. `--force` skips both confirmations.

Next it asks **Apply changes to current session?**. This sources the file in a child shell, which
can't change the terminal you ran `kunj setup` from, so open a new terminal or run the `source`
command it prints:

```bash
source ~/.zshrc
```

## 2. Jira (optional)

**Enable Jira integration?** defaults to no. If you say yes, kunj asks for:

- **Jira Cloud URL**, which must start with `https://` and be an `.atlassian.net` address, such as
  `https://acme.atlassian.net`.
- **Jira account email**.
- **API Token**, created at [https://id.atlassian.com/manage-profile/security/api-tokens](https://id.atlassian.com/manage-profile/security/api-tokens). The input
  is masked.
- **Default project key** (optional), uppercase letters only, such as `PROJ`.

It saves these to the `jira.*` settings, then tests them by calling Jira. If the test passes, it
offers to set a **Board ID** (the number in your board's URL), which the sprint features need, and
suggests `kunj jira list` and `kunj jira create` to try. If the test fails, it keeps what you typed
but turns `jira.enabled` off; fix the values with [`kunj config`](../../configuration/overview/) and
turn it back on.

<Aside type="note">
The Jira settings are saved to the configuration of the repository you run `kunj setup` in
(`~/.kunj/<repo>/config.json`), not your global configuration, and the API token is stored there in
plain text. Run `kunj setup` from the repository you use Jira with, or copy the `jira` section into
`~/.kunj/config.json` to use it everywhere.
</Aside>

## 3. Companion apps (optional)

Finally it offers the companion apps as a checklist, the same one `kunj install` shows: the VS Code
extension and, on macOS, the menu bar app. Apps that are already installed are listed as
"installed - update" and are unchecked. Tick nothing to skip. A failed download only prints a
warning and the command to retry later, such as `kunj install vscode`. See
[Companion apps](../../integrations/apps/).

## Afterwards

```bash
kj --help        # the kj alias is kunj
ksw              # pick a branch to switch to
kcom             # interactive commit
```

You can also turn on [tab completion and the PR number in your prompt](../../integrations/shell/).
