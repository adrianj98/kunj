# Overview

kunj reads configuration from two JSON files and deep-merges them over the defaults generated by the
[settings registry](/architecture/settings-registry.md):

```
defaultConfig  <-  ~/.kunj/config.json (global)  <-  ~/.kunj/<repo>/config.json (local)
```

The per-repository directory `~/.kunj/<repo>/` lives outside the working tree, so every worktree of
a repository shares one config, one `branches.json`, one set of keep files and so on. All of it is in
`src/lib/config.ts`.

# Paths

| Function | Returns |
|----------|---------|
| `getGlobalKunjDir()` | `~/.kunj` |
| `getGlobalConfigPath()` | `~/.kunj/config.json` |
| `getKunjDir()` | `~/.kunj/<repoName>`, or `./.kunj` (cwd) outside a git repository |
| `getConfigPath()` | `<getKunjDir()>/config.json` |
| `getRepoCommonRoot()` | Main worktree root (the repository itself when bare), from `git rev-parse --path-format=absolute --git-common-dir` |
| `getRepoCommonDir()` | The git common dir (`<root>/.git`, or the bare repo) |
| `getOriginUrl()` | `git remote get-url origin`, or null |
| `getRepoName()` | `repoNameFromUrl(origin)`, else the basename of the common root without `.git` |

The git calls go through `gitSync()` (`execSync`, stderr ignored, null on failure) and are cached per
process; `resetRepoCache()` clears them for tests. `repoNameFromUrl()` takes the last path segment of
an ssh, https or local URL (after `/`, `\` or `:`) and strips `.git`.

The name comes from origin, not the folder, so a bare clone or a renamed checkout still maps to the
same `~/.kunj/<repo>`. `kunj repos --json` exposes it as `kunjName`
([Repo Identity and Registry](/architecture/repo-identity-and-registry.md)).

# First Resolution Side Effects

The first `getKunjDir()` call in a process (inside a repository) also:

1. Runs `migrateLegacyKunjDir(dir)`.
2. Records the repository in `~/.kunj/repos.json` with `recordRepo(commonDir)`, which is how
   repositories reach the macOS app's list.

# Legacy ./.kunj Migration

Older versions kept state in `./.kunj` inside the working tree. `migrateLegacyKunjDir(newDir, cwd)`:

* does nothing when `newDir` already exists;
* looks for a legacy dir at `<cwd>/.kunj`, then `<toplevel>/.kunj`, that holds `config.json` or
  `branches.json`;
* copies only files git does **not** track (`git ls-files -z -- .` in that dir; if git cannot list
  them, nothing is copied), because repositories now commit `.kunj/` (blueprint, presets) and a
  committed `.kunj/config.json` must never become host config (`hooks.*`, `container.mcp`);
* never copies `blueprint.json` or `presets/`;
* creates `newDir` even when nothing was copied, so the check does not repeat, and prints
  `kunj: migrated <legacy> -> <newDir> (...)` on stderr when it copied something.

Errors are swallowed: migration is best effort.

# Loading

| Function | Behaviour |
|----------|-----------|
| `loadGlobalConfig()` | Parses the global file (creating `~/.kunj`); `{}` when missing or invalid |
| `loadLocalConfig()` | Parses the local file (creating `getKunjDir()`); `{}` when missing or invalid |
| `loadConfig()` | `deepMerge(deepMerge(defaultConfig, global), local)`; `defaultConfig` on any error |
| `loadResolvedConfig(cwd?)` | `loadConfig()` with `${...}` expanded via `expandConfigStrings()`; only resolves variables (one git call) when `treeHasVariables(config)` |

`deepMerge` recurses into plain objects only; arrays and scalars from the later layer replace the
earlier value.

`loadConfig()` returns raw templates, so `kunj config` can show `${repoconfig}/...` and the expanded
value next to it. Commands that act on values (`worktree`, `agent`, `events`, `container`, secrets key
resolution) call `loadResolvedConfig()`; see [Config Variables](/architecture/config-variables.md).

# Saving

`saveGlobalConfig()` and `saveLocalConfig()` write pretty-printed JSON (errors are logged, not
thrown). `saveConfig()` is a backward-compatible alias for the local save. `kunj config --global`
targets the global file; without it, `--set` writes the local file.
